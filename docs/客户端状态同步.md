# 客户端状态同步

Manager 自动检查六个客户端的全局配置和已登记项目配置。每 2 秒在后台比较配置内容和 Skill 目录元数据；有变化才重新扫描并更新界面。切回应用也会扫描。扫描不重叠，不读取客户端会话日志，也不启动 MCP 进程。

## 状态和来源

状态以当前客户端文件为准。分发记录只表示来源；界面来源标签为“本应用分发”。目标删除后显示“目标已移除”，可清理旧记录。配置读取失败显示“状态未知”，停止提供启停操作，不自动清理记录。

| 情况 | 显示及操作 |
| --- | --- |
| 本应用分发，当前配置存在且开关未关闭 | 配置已启用；可停用 |
| 客户端自己的配置存在且开关未关闭 | 已有配置；可停用 |
| 客户端配置中的开关关闭 | 客户端已停用；可重新启用 |
| Manager 保存过停用备份 | 已停用；可恢复 |
| 本应用分发，但目标已删除 | 目标已移除；可清理记录 |
| 读取失败或不支持的 Skill 开关表示法 | 状态未知；不可操作 |

MCP 重新启用只改当前配置的开关，保留当前地址、命令、参数和其它设置。对本应用分发的 MCP 点击停用时，保存客户端当前配置，恢复时使用这份备份。Skill 链接被改指其它位置、复制内容被改动时，仍保留删除保护。

## 已适配的持久化开关

- MCP：JSON 服务条目的 `disabled: true` / `enabled: false`；Codex TOML 服务的 `enabled = false`。
- Claude Code MCP：额外读取 `disabledMcpServers`、项目 `disabledMcpServers` 和 settings 中的 `disabledMcpjsonServers`。
- Codex Skill：读取全局及对应项目 `config.toml` 的 `[[skills.config]]` 路径和 enabled；路径匹配同时支持 Skill 文件夹、`SKILL.md` 文件及软链接解析后的中央库路径；重新启用保留其它 TOML 设置。内联数组表示法暂显示状态未知。
- 六个客户端的 Skill 目录删除、增加、链接变化和 SKILL.md 更新都会触发自动扫描。

这里的状态是本地配置状态，不是运行中会话、MCP 连通性或工具审批状态。客户端私有数据库、内存开关、插件运行时开关、CLI 本次启动参数、远端账号状态不在同步范围。其它客户端如果停用 Skill 时只修改私有状态、目录保持不变，目前不能读取这个开关；不能承诺所有客户端内部开关已经双向同步。所有客户端的实际 UI 加载行为仍需分别验收。

范围沿用 Manager 已支持的配置路径，不自动登记项目、不修改审批或权限白名单，不因外部停用而自动重新启用。MCP 配置更新后，客户端可能需要重新加载或开启新会话。

## 验证

Smoke 覆盖：六个 Agent 的配置开关关闭与重新启用、保留客户端端点、修改后的 MCP 停用恢复、目标删除、非法 JSON 状态未知、部署记录不能覆盖真实开关、Codex Skill 路径开关、项目新增及配置变更检查点。Release 构建验证 UI 和同步计时器编译。真实客户端内的点击与会话加载尚未自动化验收。

## 组合预设的失效记录

组合预览对确认已经不存在的 Skill 路径或 MCP 条目列出“待清理失效记录”，预览本身不修改记录。点击应用时，先重新确认目标不存在，再清理旧分发记录，然后部署预设所需项目；预设外的失效记录只清理，不恢复。每一步保留操作记录，可回滚。

路径仍被占用、配置无法读取、目标仍存在或预览之后发生变化时仍拦截。预览中的“冲突”只统计实际阻塞项，连带未执行项单独统计为“等待”。回归测试覆盖 JSON 与 Codex TOML、Skill 链接缺失、整个 MCP 配置文件缺失、预览无副作用、重复应用、回滚和非法配置保留记录。
